Mockito Annotations: Mock vs Inject Mock
GeeksforGeeks explained the differences between mock and inject mock annotations in Mockito, demonstrating how they create actual and dummy objects respectively. He showed that inject mock creates a real object with non-null dependencies, while mock creates a dummy object with null dependencies. GeeksforGeeks also explained when to use each annotation, recommending inject mock for functions intended to be called and mock for other cases. He concluded by discussing how to handle exceptions and showed a simple transaction service test case.

The team discussed a specific issue with transaction IDs in test cases, where the external transaction ID was found to be mandatory in the payload, and proper test cases were demonstrated to ensure code correctness and database integrity. The code coverage for the issue transaction function was analyzed, showing 41% coverage, with suggestions to improve it to around 50% by adding additional test cases for edge cases and exception handling.


Mockito Unit Testing Techniques
The instructor explained the importance of unit testing, focusing on mocking and verification techniques using Mockito. They demonstrated how to write test cases for void methods and emphasized that while mocking is necessary, verification is crucial for ensuring code integrity and preventing future developers from unintentionally breaking the code. The instructor highlighted that good test cases should fail when changes are made to the expected number of calls, ensuring the code works as intended. They also mentioned that while increasing code coverage is important, writing test cases for core business logic is more critical than for controllers, DTOs, or models.
